# 接收端 v0.6.0：托盘常驻与验证记录（2026-10-30 深夜）

## 改了什么

接收端从「黑色控制台窗口」改为**系统托盘常驻**，PyInstaller 打包从 `--console` 改 `--noconsole`。

| 行为 | 实现 |
|---|---|
| 图标三态 | 绿=有客户端推流；灰=等连接；红=fatal（如没装 VB-Cable）。Pillow 运行时画圆点，无图片资源 |
| 悬浮提示 | 一句话：状态 · 链路 · 模式（`推流中 · USB(adb reverse) · USB 模式`） |
| 右键菜单 | 状态行（禁用项，动态文字）/ 切换 USB⇄WiFi / 显示诊断日志 / 退出 |
| 切换模式 | 以 `--bind auto`（USB）或 `--bind 0.0.0.0`（WiFi）DETACHED 重启自己；置 `switching` 标志，退出时**不**执行 `adb reverse --remove-all`，避免拆掉新实例刚建的隧道 |
| 诊断日志 | `print` 全部经 `_Tee` 落盘 `%LOCALAPPDATA%\mic-bridge\receiver.log`（超 1MB 换 `.old`）；菜单项用 PowerShell `Get-Content -Wait -Tail 80` 弹实时窗口 |
| 重复启动 | 端口探测命中后弹 MessageBox「已经在运行」并退出（不再只有日志里一行字） |
| fatal 不退进程 | 没装 VB-Cable 时红盘常驻托盘，日志留原因，用户看得见"坏了" |

## 为什么黑窗口必须消失（用户原话）

> 黑色弹窗可能只能作为这种，比如功能诊断日志这种，平时肯定不能出现。

用户要的是"我现在到底有没有在推流"一眼可见：图标颜色 + 悬停提示，而不是开个窗口刷日志。

## 验证记录（全部实测）

| 项 | 结果 |
|---|---|
| 绿盘（推流中） | GDI 截屏确认托盘绿圆点；日志 31.9KB/s |
| 切换 USB→WiFi→USB | 真机各重启一次，日志两条「切换到 … 模式，重启接收端」，平板每次自动重连，32KB/s、丢块个位数 |
| 显示诊断日志 | 弹出「管理员: mic-bridge 诊断日志」终端实时滚动 |
| 防重复启动 | 安装版 EXE 二次启动弹「mic-bridge 接收端已经在运行了」，确定后进程退出（`installed_procs=0`） |
| 红盘 / 灰盘 | 待补（红盘需端口空闲时用 `--out 999` 触发 fatal 验证） |
| 端到端 | 平板说话 App 端峰值 2320（logcat 心跳 23:10:36），同窗 CABLE Output 录到峰值 1965 |
| 静默装/卸 | 3 轮：退出码 0、EXE SHA256 与 dist 一致（`968C…0888`）、目录删净、防火墙规则随装随删 |
| isreadm 修复 | 修复前静默安装弹「ShellExecuteEx 失败 2147500033」卡住用户屏幕；改 `[Run]` postinstall 后静默零弹窗 |

## 踩过的坑

1. **Git Bash 吃掉 `/VERYSILENT`**：MSYS 把 `/FLAG` 转成本地路径（`C:/Program Files/Git/VERYSILENT`），
   Inno 收到垃圾参数走完整交互向导——「静默测试」全是假的，向导弹在用户屏幕上。
   测 Windows 安装包必须 `powershell Start-Process -ArgumentList "/VERYSILENT",…` 传参。
2. **pystray 动态菜单文字**要接 `item` 参数（`text(item=None)`），否则 `TypeError`。
3. **Win11 托盘 UIA 按名字找不到图标**（tooltip 不进 UIA Name），像素扫描绿圆点 + 键盘导航
   也不稳；真机菜单交互最终靠人手点（两次切换均成功），自动化只验证到"菜单弹出+内容正确"截图。
4. **切换时的 reverse 竞态**：老实例退出会 `adb reverse --remove-all`，可能拆掉新实例的隧道；
   用 `st["switching"]` 标志跳过清理。
