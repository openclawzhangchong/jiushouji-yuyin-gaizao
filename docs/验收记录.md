## 1. 传输不丢不堵

平板端每 5 秒一条 logcat 心跳（`MICBRIDGE:V`）：

```
I/MICBRIDGE: 已连 127.0.0.1:5005 音源=VOICE_COMMUNICATION minBuf=1280 用=5120
I/MICBRIDGE: 心跳 已推 5s   累计 154240B   速率 30416B/s 峰值 791  欠采 0 重连 0  状态 采麦中
I/MICBRIDGE: 心跳 已推 235s 累计 4455040B  速率 32640B/s 峰值 660  欠采 0 重连 14 状态 采麦中
```

| 指标 | 实测 | 期望 |
|---|---|---|
| 上行速率 | **31603 – 32640 B/s**（多窗口） | 满速 32000 B/s（16000×2） |
| 欠采（AudioRecord 读到不足一包） | **0** | 0 |
| 丢块（接收端超水位丢弃） | **0** | 0 |
| 接收端缓冲水位 | 40 – 140 ms 来回，**不持续增长** | 有界 |
| UDP 侧对照（spike 阶段） | 发 200 包 / 收 200 包，进 4.00s 出 4.00s | 零丢、时长精确 |

`minBuf=1280` 是 `getMinBufferSize` 的返回值（**字节**，即 640 样本 = 40ms），实际申请 `min*4=5120` 字节。

## 2. 真语音识别（决定性的一条）

方法：**让平板自己外放已知中文，再用它自己的麦克风听进去**（不依赖人说话，
也不依赖电脑有没有喇叭 —— 这台主机显示器 MG2461VI **没有扬声器**，电脑外放这条路只会得到假失败）。
素材 `/sdcard/Music/loop2.wav.off`（≈10.9s，24kHz）。

链路：平板外放 → 平板麦克风 → AudioRecord → TCP(adb reverse) → pc_receiver → CABLE Input
→ **CABLE Output 录成 verify.wav** → CapsWriter-Offline 的 Qwen3-ASR（`ws://127.0.0.1:6016`）

ASR 返回（`is_final=true`，服务端处理 1639ms，端到端 1644ms）：

> **Hello 啊，我是小智啦。声音好听的台湾女孩一枚，超开心认识你耶。最近在忙啥？别忘了给我来点有趣的料哦！**

中间结果（`is_final=false`，累计 15s 时）也一致，末尾多吐了一个「我。」（当时刚进尾音段）。
**整句逐字正确**，包括标点。

### verify.wav（34.2s @16kHz mono）包络

| 时间段 | 平均 RMS | 峰值 | 含义 |
|---|---|---|---|
| 0 – 5 s | **-96.7 dBFS** | -96.3 | **数字零** —— 平板还没连上，接收端补静音（证明没有伪造的底噪） |
| 5 – 6 s | -51.9 dBFS | -50.8 | 环境底噪 |
| **7 – 16 s** | **-8.7 dBFS** | **-3.3** | **外放段**，强信号，长度对上素材 |
| 17 – 34 s | -48.5 dBFS | -42.5 | 回到环境底噪 |

整段 peak 0.9885（=32390/32768），整段 RMS 0.1775。

分频带能量（全段 FFT）：`0-100:9.1  100-300:10.7  300-1000:111.4  1000-2000:182.8  2000-4000:42.1  4000-8000:9.1`
→ **1000-2000Hz 最强、4kHz 以上快速滚降**，是语音形状，不是电流噪声。

## 3. 虚拟声卡本身的透传质量（spike 阶段，同主机同驱动）

| 指标 | 实测 |

| 分频带能量比（源 vs 采集） | 100-500 / 500-1k / 1k-2k / 2k-3.5k / 3.5k-6k Hz **全部 1.000 ± 0.01** |
| 总能量比 | 1.0045 |
| 皮尔逊 r | 0.865（<1 的原因**只是** 16k↔44.1k 重采样的**相位**抖动，频带能量证明无频率损失） |
| 16000Hz / 单声道 请求 | 支持（MME、DirectSound 两档都可开 16k mono） |

## 4. 断线自动恢复

1. `taskkill` 掉 `pc_receiver.py` → 平板端立刻 `SocketException: sendto failed: ECONNRESET`，
   随后 `ConnectException: ECONNREFUSED`，退避 **1s → 2s → 4s → 8s**（封顶 5s 的逻辑在 0.3.2 修正）。
2. 重新启动 `pc_receiver.py` → 平板端**自己**重新连上并继续推流，全程零人工：
   ```
   I/MICBRIDGE: 已连 127.0.0.1:5005 ...
   I/MICBRIDGE: 心跳 已推 129s 累计 1084800B 速率 30434B/s 峰值 858 欠采 0 重连 14 状态 采麦中
   ```
   接收端侧 `连接 2`（第二次 accept），水位立刻回到 40–80ms。

## 5. 熄屏续流

```
adb shell input keyevent 26        # 熄屏
dumpsys power → mWakefulness=Asleep, Display Power: state=OFF
（保持熄灭 75 秒）
```

熄屏期间 **14 条心跳全部满速**（31603–32640 B/s），欠采 0，无断档。
`dumpsys power` 确认 `PARTIAL_WAKE_LOCK 'micbridge:up' (uid=10058, pid=…)` 持有。

> ⚠️ 只验了 75 秒，**没跑 30 分钟 soak**。

## 6. 延迟

| 配置 | 端到端（发出冲激 → 在 CABLE Output 出现） |
|---|---|
| DirectSound 设备 + 默认 latency | 330 – 340 ms |
| **WDM-KS/MME + `latency=low` + block 320** | **143.9 ms** |
| 同上 block 128 / 64 | 162.4 / 158.1 ms（更小只增加欠载，不降延迟） |

**没测的部分**：平板端整链的绝对延迟。跨机时钟对齐需要 `adb shell date`，其往返延迟是几百 ms 量级，
撑不起 ±30ms 的结论，所以只给组成估算：
`Windows 段 ≈144ms + 平板 20ms 分块 + USB ≈1ms + 接收端水位 40–140ms ≈ 160–300ms`。
对"语音输入/听写"这个用途不敏感（自己不听自己的）。
